## [2.0.0-alpha.9] - 2026-10-17
### Added
- The tracefile event vocabulary gains `0x0f STRANDED`: bracket framing buffered on an input port whose senders have all terminally disconnected, reported at the moment it became inevitable. Payload: the flat tuple `[tgt_node, tgt_port, scope|null, open_count, close_count]` (work document #40 update #13)
- `0x49 CMD_STREAM_OPEN` and `0x4A CMD_STREAM_EOT` (work documents #40, #45): the client-driven stream surface. `0x49` opens a persistent stream into an exported inport — a driver socket the port stays connected across, with back pressure respected; packets flow via `0x47 CMD_PACKET_SEND`. `0x4A` signals end of transmission: the runtime disconnects the driver, the boundary reaches EOT, and the network's drain-based closing cascade runs. Duplicate opens and stray EOTs answer `0x17 REASON.INVALID_STATE`. Boundary stream lifecycle is observable as `0x0b CONNECTION_OPEN` / `0x0c CONNECTION_CLOSE` with a nil source; the tracefile decoder emits the boundary payload form

## [2.0.0-alpha.4] - 2026-10-16
### Changed
- `REASON` registry for `0x17 CMD_OP_REJECTED` (work document #4 update #43, from the MicroFlo constrained-runtime port): non-`0x14` rejections answer `detail: { reason: <code>, message? }` — a normative uint8 code vocabulary (`0x00 UNSPECIFIED` … `0x0b UNKNOWN_TARGET`) mirroring the `0x02` limitation codes where semantics overlap, so clients can programmatically distinguish "may not" from "cannot" from "malformed". Additive; closes SPEC §6's open stub-error item (`0x09 STUB` on rejections, `0x09 STUB_ERROR` telemetry for engine-raised)
- `assembleTraceFileFromRecorder` now projects the recorder's metadata into the DATA event payload envelope `[src, tgt, value]` instead of dropping it (external review, update #35 point 1: the event stream maps onto the frame-1 topology), and the chunk frame carries the plane id
- The tracefile projection follows the §7 payload rules exactly (work document #4 update #42): the envelope is DATA-only — bracket events keep their plain label payloads (the wire event-type
  vocabulary renames to `BEGIN_BRACKET`/`END_BRACKET`) and connection events project to the flat `[src_node, src_port, tgt_node, tgt_port]` ref pair; the live telemetry path (in `@noflo/runtime`) now carries the same envelope, so every producer conforms to the spec'd shapes
- Clock provenance (work document #4 update #43): SPEC §7 records that timestamp fields carry the recording runtime's clock with provenance as runtime policy — monotonic-derived counters (hybrid logical clocks) are conforming, consumers MUST NOT assume cross-runtime UTC alignment, and `0x48` `uptime_ms` stays monotonic by definition
- Subgraph planes (work document #4 update #42): SPEC §5 documents the runtime-reserved `sg/` plane id prefix, subgraph-plane registration at network build, the `0x17` refusal for subgraph-plane drops (and the cascade to descendants when an ephemeral plane drops), and §7 records the effective-plane attribution rule — subgraph-sourced events attribute to the subgraph's plane and the engine's internal path never travels the wire
- Constrained-profile advertisement and frame interpretation rules (work document #4 update #43, from the MicroFlo ESP32 port): SPEC §4 gains a SHOULD-registry of well-known `runtime_metadata` keys (`planes`, `value_model`, `source`) and §3 pins the announce app_data's frozen three-element shape as normative; §5 requires main-plane-only runtimes to answer `0x16` main-only and non-main commands with `0x17 UNSUPPORTED`; §1 gains the frame-interpretation rules — unrecognized opcodes answer `0x17 UNKNOWN_COMMAND`, known-but-unhandled commands answer `0x17 UNSUPPORTED`, undecodable frames answer `0x17 MALFORMED`, links never tear down, and unknown flowtrace event types are skipped structurally. `decodeFrame` annotates unknown-command errors with the reason code; the runtime server answers instead of staying silent
- Payload fidelity (work document #4 update #43): SPEC §8 requires that values outside a runtime's declared value model (§4 `runtime_metadata` `value_model`) never crash or corrupt state — `0x47` and IIP inserts answer `0x17 PAYLOAD_UNSUPPORTED`; runtime-generated values are in-model by construction, so telemetry needs no gate
### Added
- Plane addressing (work document #4 updates #24–#33): the graph-sync block (`0x10`, `0x11`, `0x12`, `0x14`) gains a nil-defaulted `plane_id` — one plane per graph instance (the main graph, node-anchored subgraph instances, client-minted ephemera); the handshake replies name the plane and epoch
- `0x15 CMD_PLANE_DROP`: one-command ephemeral plane teardown — stops the network and discards state wholesale; the main plane is not droppable
- `0x16 CMD_PLANE_LIST`: the plane tree — every running graph instance with its kind, parent, node id, component name, and label
- `0x17 CMD_OP_REJECTED`: the runtime's explicit no — permission denials per plane and structural rejections, carrying the op identity triple so clients revert their mirrors
- `0x26 CMD_COMP_SOURCE`: the read counterpart of `0x25` — pull component source from the runtime
- `0x47 CMD_PACKET_SEND`: plane-addressed input injection — interactive use, remote fbp-spec cases, and the runtime-as-remote-component pattern
- `0x48 CMD_GET_STATUS`: run state, uptime, epoch, and the advertised capability ceiling
- Auth response (`0x02`) carries runtime metadata and the advertised capability ceiling alongside the granted mask
- `EVENT_TYPE` gains `CONNECTION_OPEN` (0x0b) and `CONNECTION_CLOSE` (0x0c) — the framing 1.x UIs animate edge activity with
- `ComponentDetail` carries component-level `description` and `icon`. The flat `values`/`default` inport options are not carried on the wire — they stay publish-time manifest data pending the end-to-end schema design (work document #37 §3.4: inline schemas supersede them)
- The `0x32` chunk frame gains a `plane_id` at position 2, and DATA event payloads carry the positional envelope `[src, tgt, value]` so the event stream maps onto the frame-1 topology
- `assembleTraceFileFromRecorder` (work document #23 update #2): the binary encoding of the NoFlo core trace recorder's `toJSON()` state — snapshot fields framed as the `0xF0` snapshot, event tuples projected to a `0x32` chunk frame based at the recording start, the recorder's optional fourth metadata element projection-dropped so wire payloads stay the raw value. Consumed duck-typed with no dependency on `@noflo/noflo` (the protocol package stays runtime-agnostic); a round-trip spec in `@noflo/runtime` pins the JSON and binary representations together

## [2.0.0-alpha.3] - 2026-10-10
### Added
- Initial wire-constant module for FBP Protocol 2.0 over Reticulum (work document #4): the `fbp.runtime` announce aspect (`ANNOUNCE_ASPECT`, work document #4 update #21), command codes for the transport/identity, CRDT graph synchronization, component registry, execution control, and telemetry blocks, the capability mask and limitation codes, graph op types, flowtrace event types, visual-state formats, the shared `elementary | subgraph | stub` component-type vocabulary (#25/#4 update #11), and the `0xF0` trace-snapshot frame code. Lifecycle transition codes are pinned per work document #4 §7, including the `FAILED` transition encoding with its detail carried in an accompanying `0x04 ERROR` event (#4 update #1) and the `PAUSED`/`RESUMED` run-state codes, plus the `BREAKPOINT_HIT` flowtrace event type carrying the breakpoint cause
- `0x40` block execution control & debugging codecs (work document #4 §8): run control — pause, resume, and step (noflo/noflo-ui #243), plus start and stop (#4 update #20): the lifecycle control the `LIFECYCLE_CTRL` capability names — data breakpoints with client-chosen link-scoped ids and nil-matches-any triggering inport (#245), and per-process disable/enable with queued packets kept rather than dropped (#317); all commands require the `LIFECYCLE_CTRL` capability, with no dedicated ack frames — run-state changes ride the telemetry stream as `PAUSED`/`RESUMED` lifecycle events and breakpoint hits as `BREAKPOINT_HIT` events
- `0x44`/`0x45` live process listing codecs (work document #4 update #9): a bare request and the authoritative runtime view as `[0x45, epoch_id, {node: [component, kind, state]}]` — the declared component kind travels with every node so clients never infer stub-ness by joining names against their own registries, and the per-node execution state mirrors `0x43`; the listing is introspection and requires `GRAPH_READ`, not `LIFECYCLE_CTRL`
- `0x09 STUB_ERROR` flowtrace event type (work document #4 update #9): the canonical classification for errors raised by stub components — the payload is the exception string exactly as in `0x04 ERROR`, but the event type itself marks the error as unimplemented rather than a genuine component failure, with no string-parsing convention
- `0x46 CMD_HWM_SET` codec (work document #4 update #9): the runtime-global high-water mark as `[0x46, high_water_mark]` — non-negative integer (`0` synchronous, `n` up to `n` admitted in-flight packets) or nil (unbounded); the global default in the backpressure hierarchy, runtime configuration rather than graph state, observable through `0x0a EDGE_CAPACITY` samples. Edge-level high-water marks need no new wire surface: they travel as edge metadata inside `0x14` payloads, with changes projecting to tombstone + insert per #4 update #8
- `0x0a EDGE_CAPACITY` flowtrace event type (work document #4 update #9): per-edge backpressure sampling, one event per edge per flush with the `[edge_id, in_flight, desired_size]` payload — `desired_size` nil when the edge is unbounded, cadence riding the subscription's flush policy; a data-channel observation, never an error channel, feeding the noflo-ui high-water-mark route visual vocabulary
- Announce app_data (`msgpack([protocol_version, destination_hash_raw16, node_name])` per #4 updates #6/#7) and `0x02` auth response codecs with the version byte ahead of the capability mask, built on `@reticulum/core`'s zero-dependency MsgPack codec, with golden byte vectors pinning the wire layout
- `0x10` block CRDT graph codecs: epoch sync request with client logical clocks, up-to-date short-circuit, stale epoch with Reticulum Resource hash, and bidirectional `0x14` updates; the op taxonomy is now a *total* projection of the changeset reference model — insert ops for every structural entity kind (node `0x01`, edge `0x02`, IIP `0x03`, export `0x06`, group `0x07`, additive per #4 update #7), shared tombstone, UI metadata `0x05` — with the payload mapping documented per op (entity definition without id; `entity_id` carries it) and node renames projecting to tombstone + insert at the changeset→protocol boundary (#4 update #8)
- `0x20` block Two-Step Cache codecs: registry sync, the `0x21 CMD_COMP_UP_TO_DATE` match reply mirroring the graph block's `0x11` (the runtime always answers a sync request; silence never carries semantics), manifest (name → `[sig_hash, kind]` tuples carrying the declared component kind per #4 updates #9/#11, valid with signature and no source per #4 update #8), detail request/response carrying the declared component kind and the full #25 port field set as maps with absent optionals omitted, atomic source writes, and package install requests; plus the canonical signature and manifest serializations (sorted-key JSON) with SHA-256 `sig_hash` and `registry_hash` computation as the cross-repo alignment substrate with noflo-ui #43 (#4 update #10) — the registry-hash algorithm is now pinned, since it was previously unspecified on the wire
- `0x30`/`0x32` streaming telemetry codecs: pub/sub subscriptions with client-requested flush intervals, flowtrace chunks carrying delta-encoded `[time_delta_ms, event_type, payload]` tuples with uint32 delta validation, and a builder converting absolute-timestamped engine events into a chunk based at the earliest event
- `ProtocolError` carrying the offending opcode, thrown on truncated frames, unknown opcodes, wrong arities, and malformed payloads across all codecs
- AsyncAPI 2.6.0 interface document (`asyncapi.json`, CC0-1.0) describing one channel per command code with explicit direction, fixed-arity positional payload schemas, per-channel capability-mask requirements, and the RNS bootstrap transport (announce app_data schema and the `0x02` handshake), including the LXMF store-and-forward payload and the streamable trace file as non-link messages; machine-verified against the implementation by a test suite that decodes every wire example through the real codecs, re-encodes byte-for-byte, validates the documented decoded payloads against the wire bytes, and checks one-to-one parity between the channel table and the command constants (#4 update #7)
- Top-level `decodeFrame` dispatch: any link-level frame decodes through one entry point keyed by its leading opcode, returning a `cmd`-discriminated object; the `0xF0` trace snapshot is deliberately not dispatchable (file format, not a link frame)
