## [Unreleased]

## [2.0.0-alpha.11] - 2026-10-18
### Added
- **noflo**: Per-instance port behavior via node metadata (work document #44): the core-owned `noflo.*` keys — `noflo.control: string[]` (the instance's complete gate-inport set, replacing the declaration), `noflo.scoped: object` (port-name → boolean, buffer structures re-prepared on flip), and `noflo.forwardBrackets: object` (per-inport rule replacement, including the framing-termination empty rule) — applied by the network after instantiation and before wiring. Overrides are per-instance, validated loudly (unknown `noflo.*` keys, nonexistent ports, and mistyped values are build errors named with the node id), and the zero-regression posture holds: a node without `noflo.*` metadata is untouched. Three rejections ship with the slice: subgraph nodes are excluded (the relay semantics for exported ports are not defined — place the override on the inner graph's node), `noflo.scoped` is inports-only (the outport-side flip interacts with the ordered-output and forwarding machinery and needs its own design pass), and addressable inports cannot be promoted to gates (the control-triggered walk does not scan addressable buffers — a promoted addressable port would strand its arrivals). The keys' governing contract ships as the `noflo/port-behavior` schema artifact — `schemas/port-behavior.json`, pinned by digest in the package's new `noflo.json` manifest's schemas table and loaded into a runtime's schema table at startup — so protocol clients fetch the vocabulary through the Two-Step Cache (`0x29`, with mandatory client-side digest verification and closure completeness) without any project-authored writes; the runtime helper validates the subset a running network can check, and the opt-in commitment stays a publish-time contract (work documents #37/#25). Packaging note: the tarball now ships `noflo.json` and `schemas/`
- **assembly-utils**: `ToAssembly` accepts the `assembly.field` node metadata to name the field the incoming value lands under (default `data`): the envelope creation goes stock — e.g. `field: "path"` turns a bare path string into `{ errors: [], path: value }` for a downstream adapter consuming `path`. The error envelope stays `{ errors: [error] }` regardless of the field
### Changed
- **noflo**: Port names are case-significant (work document #15): the 1.x lowercase-only port-name constraint is retired and author casing is preserved end to end — `out` and `OUT` are distinct ports, and a case-mismatched graph reference fails loudly at network build instead of silently resolving. Legacy FBP JSON documents carrying `caseSensitive: false` (the 1.x interchange default) import with port names normalized to lowercase
- **noflo**: The `HasValidationCallback` typedef documents the framing-aware validator form: the callback gains the optional `brackets` parameter — the bracket payload stack at the walk position, passed by `hasStream`'s framing-aware walks (a data IP inside one open bracket sees a stack of one; a bare data IP an empty stack) — while plain `has`/`hasData` walks stay stateless per-IP checks and leave it undefined. The runtime already passed the stack; the typedef now declares it, so components can decide their firing pattern from a stream's framing through the public API ("fire when the framed token stream has completed and holds N packets") without reaching into `InPort.getBuffer` internals
- **assembly**: `asAssembly`'s out-mapping accepts `null`: the mapped outport's inner output replaces the message entirely — the transform-the-message shape (a component that mutates and forwards the message, e.g. `packets/ScopeFromObject`) — and the named fields merge on top of the replacement, so the result is independent of the inner component's outport declaration order. The replace output must be a plain object; anything else (a non-object, an array, a class instance) accumulates an error into `msg.errors` instead of replacing. Only one outport may map to `null`; `asAssembly` validates loudly at wrap time (work document #36's mapping vocabulary, the out-side completion of the whole-message mapping)
- **assembly-utils**: `CollectFields` honors `null` entries in its `fields` config as the whole-message replace mapping: the collected inner output becomes the message and supersedes the incoming envelope's error state — the inner received the full envelope and owns the accumulation, so a relay-convention inner carries the accumulated errors forward in its replacement and the collector's error port remains the out-of-band channel (merging the two channels would double-count the envelope's original errors) — with a non-object output accumulating an error instead (the collector-side of `asAssembly`'s `null` out-mapping)
- **graph**: FBP JSON import honors the document's `caseSensitive` flag (work document #15): legacy documents carrying `caseSensitive: false` (the 1.x interchange default, where the reference parser lowercased port names) import with port names folded to lowercase across edges, IIP targets, and exports — both the public export name and the internal reference — so mixed-case references against lowercase-declared 1.x components resolve. `caseSensitive: true` or absent preserves casing as authored, and a case-mismatched reference fails loudly at network build instead of silently resolving. The fold builds a fresh document — the caller's object is never rewritten — port values must be strings (the normalization does not coerce), an export-name case collision throws rather than silently dropping one, and top-level `inits`/`case` fields survive legacy normalization on modern documents
### Fixed
- **noflo**: The IIP-buffer check in plain `has()` could be poisoned by a partially open regular stream: the validator traveled as a bare callback, so the bracket-walk state built during the regular-buffer walk carried into the IIP-buffer walk — an IIP-fed standing value beside an unfinished stream read as being inside brackets. The validator now travels as a factory through the whole `has()` chain (`ProcessInput.has`, `hasStream`, and `InPort.has`), and every buffer walk gets fresh framing state; `hasStream`'s non-control path calls `InPort.has` directly with its factory (work document #47; the follow-up ledger's per-walk item, now closed for the control and non-control paths alike)

## [2.0.0-alpha.10] - 2026-10-17
### Changed
- **noflo**: One firing rule for all ports: an arrival on any port re-fires the process once per scope that holds unprocessed input on any non-control port — control buffers are standing state — with the arriving IP — stamped to the firing scope — as the activation's context. The firing predicate is any buffered IP in the scope (data and brackets both); control ports keep their buffering semantics (non-consuming reads, the standing stream) and lose their firing role — their buffers are standing state, never pending work; forwarding inports are exempt (the forwarding machinery owns their brackets). Control-port arrivals no longer fire a scopeless activation that could not see scoped buffers — standing configuration arriving after scoped messages now re-fires the waiting processes instead of stranding them (the shape that stranded burst messages behind late-arriving configuration in wrapped-adapter pipelines; found by the noflo-jekyll burst investigation, work documents #35/#36). The 1.x `triggering` port option is removed from the typed and documented option set (work document #47, delivering the semantics trustmaster articulated in the noflo/noflo#607 discussion); a source still declaring it passes it through as an unknown key and it does nothing. The determinism contract — identical results under every arrival-order permutation — is pinned by `spec/FiringModel.js`
- **assembly**: `asAssembly` generated graphs wire each field extractor's `error` outport into the result collector's error accumulation, so an extractor's missing-field failure completes the message on the error leg instead of stranding the collector's wait for a field that will never deliver (work document #35 update #13)
- **assembly-utils**: `ExtractField` signals a missing mapped field on the `error` outport instead of silently delivering `undefined`: the generated adapter graphs wire the extractor's error leg into the collector's error accumulation, so a message lacking a required field completes on the error leg with the failure recorded, rather than crashing the inner component on a null deref. A field that is present with a `null` value is a value and delivers (work document #35 update #13, question (b))
### Fixed
- **noflo**: The stream-completeness check on control ports: `hasStream`'s bracket-aware walk was destroyed by the control-port `has()` wrapper (bracket IPs were filtered out of the validator, so the stream-framing tracking never saw them), making a control stream's completeness gate report true for any partially open stream — a collector gating on a standing control stream fired early, baking incomplete results downstream (the shape behind the noflo-jekyll footer-include race). `hasStream` now takes the framing-aware check on control ports: the buffered stream's framing decides completeness, and the closeBracket completing a stream with data inside is the completion moment. Plain `has()` keeps the data-presence semantics — buffered brackets alone do not satisfy it (work document #47; caught by the firing matrix)
### Documented
- **assembly-utils**: `CollectFields`: the error contract is normative in the component docs — the inner's `error` port is the message's terminal event for its scope (the collector fires with the errors and whatever fields delivered); inner data arriving after the error for the same scope has no collector waiting and surfaces in the shutdown diagnostics. Pairing is per scope via the scope-aware has-checks (work document #35 update #13, question (c))

## [2.0.0-alpha.9] - 2026-10-17
### Added
- **noflo**: Per-run initial re-delivery and cycle-graph delivery counts pinned by spec (`spec/InitialRedelivery.js`): a cycle's packet delivers exactly once per arrival per run (the IIP and its echo — two arrivals, no duplication), an explicit restart re-posts the graph's IIPs (per-run semantics, the work document #45 gate 3 design decision), and component instance state persists across restarts. Instrumented investigation of the PR #1092 review's cycle-graph observations found no genuine duplication or fan-out miss against current master (work document #46)
- **fbp-protocol**: The tracefile event vocabulary gains `0x0f STRANDED`: bracket framing buffered on an input port whose senders have all terminally disconnected, reported at the moment it became inevitable. Payload: the flat tuple `[tgt_node, tgt_port, scope|null, open_count, close_count]` (work document #40 update #13)
- **fbp-protocol**: `0x49 CMD_STREAM_OPEN` and `0x4A CMD_STREAM_EOT` (work documents #40, #45): the client-driven stream surface. `0x49` opens a persistent stream into an exported inport — a driver socket the port stays connected across, with back pressure respected; packets flow via `0x47 CMD_PACKET_SEND`. `0x4A` signals end of transmission: the runtime disconnects the driver, the boundary reaches EOT, and the network's drain-based closing cascade runs. Duplicate opens and stray EOTs answer `0x17 REASON.INVALID_STATE`. Boundary stream lifecycle is observable as `0x0b CONNECTION_OPEN` / `0x0c CONNECTION_CLOSE` with a nil source; the tracefile decoder emits the boundary payload form
- **runtime**: Client-driven streams (work documents #40, #45): `0x49 CMD_STREAM_OPEN` attaches a persistent driver socket to an exported inport, `0x47 CMD_PACKET_SEND` flows through the open driver with back pressure respected, and `0x4A CMD_STREAM_EOT` disconnects it — the boundary reaches end of transmission and the network ends drain-style. Without an open stream, `0x47` keeps its self-contained single-packet IIP semantics. Rejections: duplicate open, stray EOT, unknown port, non-running plane. The stream lifecycle records as `0x0b CONNECTION_OPEN` / `0x0c CONNECTION_CLOSE` telemetry events (nil source — the sender is outside the graph)

## [2.0.0-alpha.8] - 2026-10-17
### Removed
- **noflo**: The closing check no longer runs per delivered packet on every event-loop turn: the evaluation is debounced per `closingDebounceMs`, keeping the 10k-node stress network at ~1.4s
### Added
- **noflo**: `Network#closingDebounceMs` option: the coalescing window for the closing evaluation (default 10ms). Scheduling only — the closing predicate is evaluated at most once per window, and the end fires at the first evaluation after the state completes
- **noflo**: `Component#isClosedDown()` and the `closedown` lifecycle event: the cascading-closedown state (every input at EOT, no open activation, nothing buffered to deliver) with terminally disconnected outports. Subgraph wrappers close down with their inner networks
- **noflo**: `InPort#isEot()`: whether the input is at end of transmission (EOT) — every attached socket terminally closed by its sender. EOT is unscoped by definition: it is a fact about the sender, not about a stream or scope
- **noflo**: `spec/NetworkClosing.js` pinning the closing sequencing: every closedown event before the network end, a revived component's second closedown gating the end, the nested order (inner end, wrapper closedown, outer end), and feedback cycles targeting exported inports ending instead of deadlocking
### Changed
- **noflo**: Drain-based network closing (work document #45): the quiet-window timer is replaced by boundary-owned end-of-transmission. A network ends when every boundary input is at end of transmission and the network is quiescent — no open activations, no packet in flight on any edge. Internal edges and cycles need no closedown: a quiescent network with all sources finished is absorbing (no future event can occur inside it). Networks with live boundary drivers — long-running graphs, remote subgraphs, generators — never end from internal quiet; the boundary owns end-of-transmission
- **noflo**: Sending no longer disconnects: `InternalSocket.post` auto-connects but never auto-disconnects — per-burst disconnect framing is superseded by in-band brackets, and `disconnect()` is sender-terminal end-of-transmission (the 0.x intent). Components that ended a transmission by disconnecting must call `disconnect()` explicitly, or rely on drain-based closing
- **noflo**: The activation contract is load-bearing: a void `process()` resolution means "the process already sent" — deferred sends must hold the activation open (resolve the promise with the value; the bridge sends in-activation). An out-of-activation send races drain-based closing and re-opens a closed-down downstream that can never trust end of transmission again. Self-driven generators hold their activation across emissions (as the migrated generator components already do), so they are never closed down mid-generation
- **noflo**: `OutPort.sendIP()` drops the `autoConnect` parameter: sending auto-connects; disconnecting is the sender's explicit decision
- **nodejs**: The mesh attach (Reticulum init, identity load, and the runtime bind) now precedes the network start: a graph that finishes immediately under drain-based closing can no longer exit the process before the runtime has announced on the mesh. The announce line in batch mode therefore always precedes the run
- **nodejs**: The host start gates on the persistor hydration only (`rns.persistorLoadPromise`) instead of `rns.ready()`: the latter also awaits the AutoInterface discovery start promise, which never settles on hosts without usable multicast connectivity (CI containers, offline machines) — the discovery start must not block the program. Announcing to nobody remains the documented behavior for interface-less hosts (upstream @reticulum/core should still fix the unsettled start promise)
### Fixed
- **noflo**: A feedback edge targeting an exported inport no longer deadlocks the network end: the closing predicate's boundary check counts only external sockets (driver-attached and IIP); internal edges targeting the same port are covered by quiescence
- **noflo**: A socket attaching to a closed-down component's outport goes terminal immediately — a late-attached edge no longer leaves its receiving port waiting for an EOT that will never fire
- **noflo**: Subgraph wrappers mark end of transmission with their inner networks: the shared-port EOT state reflects the deepest sender's condition, not the wrapper's completion

## [2.0.0-alpha.7] - 2026-10-16
### Added
- **noflo**: Process activation events in the trace stream (work document #43): `Network` emits an `activation` event with `{ id, load, ended }` payload on every component activation and deactivation (the same signal end-detection already consumed internally), subgraph networks forward their inner activations with the subgraph path prepended, and the `Flowtrace` recorder records them as `ACTIVATION_BEGIN` (`0x0d`) and `ACTIVATION_END` (`0x0e`) flowtrace events with the positional `[node_id, load]` payload — load after the change, `0` marking a node going idle. Trace replay can now answer "why didn't the network finish": the last activation that never deactivated is the hung process, with `load` showing concurrent activations. The vocabulary mirrors `@noflo/fbp-protocol` per the round-trip pin
- **assembly**: The `assembly` metadata catalog (work document #37 phase 2): the config-class `assembly.field` key, declared in the digest-addressed `schemas/catalog.json` artifact (pinned to the `@noflo/fbp-protocol` meta-catalog's shipped digest) with a dependency-free `src` mirror. `asAssembly`-generated adapter nodes now carry the namespaced key, and the adapter components read it via `getComponent(metadata)` — the declared form of the configuration mechanism work document #36 exercised. ### Changed
- **noflo**: `Subgraph` is constructed with its graph and network options: `new Subgraph(graph, options)` takes the same options a `Network` takes (`componentLoader`/`registry`/`flowtrace`/`asyncDelivery`/`highWaterMark`) plus `metadata`, builds its internal network from the constructor, and exposes the completion as `subgraph.prepared`. ### Fixed
- **noflo**: Subgraph internal networks are guarded against concurrent and redundant starts: `setUp` no longer stops-and-restarts an already-running internal network when the parent network (or an explicit `component.start()`) starts the subgraph after its implicit data-triggered start — a cycle that tore down internal component state and re-delivered initials. The guaranteed contract is that a subgraph delivers its internal IIPs during the network start that activates it (the parent network's start, or an explicit `start()`), before any data is processed; data sent to a never-started bare subgraph component before `start()` still races the implicit start and is not guaranteed to see the IIPs

- **runtime**: Broadcasts no longer reach peers whose granted capabilities do not cover the frame (work document #30)
