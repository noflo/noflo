## [2.0.0-alpha.3] - 2026-10-10
### Removed
- **noflo**: `BaseNetwork`: the abstract base class was a `subscribeGraph`-era relic — with `LegacyNetwork` gone and graph mirroring mandatory, `Network` is the single network class. All mechanics (sockets, process management, lifecycle) now live directly on `Network`; the public API surface is unchanged apart from the class no longer being subclassable
- **noflo**: **Legacy (pre-Process API) component support**: `Component.isLegacy()` and the `__openConnections` connection-counting activation path are gone — components must use the Process API. The loader no longer warns on legacy components; networks track active processes via component `load` only. Legacy components in a graph now fail instead of silently half-working
- **noflo**: Passing a `componentLoader` via graph metadata: the `Network` constructor no longer falls back to `graphMetadata().componentLoader` — pass it via network options or the application registry
- **noflo**: Dead utility surface: `Utils.isArray` (polyfill-era), `Utils.guessLanguageFromFilename` (loader-node carries its own), the unused `ErrorableCallback` typedef in `Component`, and the vestigial `_callbacks` port-key exclusion in `ProcessOutput`
- **noflo**: `noflo.isBrowser()`: the public environment-sniffing helper is gone along with its internal uses. Platform differences are handled by capability checks (`typeof process`, `setImmediate` availability) inside `Platform` — `deprecated()` and `makeAsync()` keep identical behavior on Node, Deno, Bun, and browsers
- **noflo**: The 1.x network-level `begingroup`, `endgroup`, and `data` events: networks emit the `ip` event (whose detail carries the bracket type) instead of re-emitting each IP as a separate legacy event. Port-level bracket events and the Flowtrace event vocabulary are unaffected
- **noflo**: The 1.x socket-level packet events: `InternalSocket` emits only `ip` for delivered packets (plus `connect`/`disconnect` connection framing) — the derived `data`/`begingroup`/`endgroup` events and the `handleSocketEvent` send-side shim (where `send()`/`beginGroup()`/`endGroup()` expressed themselves as legacy event names converted back into IPs) are gone. Sockets take pure IPs: `post(new IP(type, data))`, and ports use the `openBracket`/`closeBracket`/`data` methods. Connection framing stays on `connect`/`disconnect`
- **noflo**: The legacy `integer` port datatype normalization in `BasePort`: `datatype: "integer"` on a port now fails options validation with the list of valid datatypes — use `int`
- **noflo**: `Platform.deprecated()` and the `NOFLO_FATAL_DEPRECATED` environment variable: with every deprecation call site removed there is no warning machinery left to configure
### Added
- **fbp-protocol**: Initial wire-constant module for FBP Protocol 2.0 over Reticulum (work document #4): the `fbp.runtime` announce aspect (`ANNOUNCE_ASPECT`, work document #4 update #21), command codes for the transport/identity, CRDT graph synchronization, component registry, execution control, and telemetry blocks, the capability mask and limitation codes, graph op types, flowtrace event types, visual-state formats, the shared `elementary | subgraph | stub` component-type vocabulary (#25/#4 update #11), and the `0xF0` trace-snapshot frame code. Lifecycle transition codes are pinned per work document #4 §7, including the `FAILED` transition encoding with its detail carried in an accompanying `0x04 ERROR` event (#4 update #1) and the `PAUSED`/`RESUMED` run-state codes, plus the `BREAKPOINT_HIT` flowtrace event type carrying the breakpoint cause
- **fbp-protocol**: `0x40` block execution control & debugging codecs (work document #4 §8): run control — pause, resume, and step (noflo/noflo-ui #243), plus start and stop (#4 update #20): the lifecycle control the `LIFECYCLE_CTRL` capability names — data breakpoints with client-chosen link-scoped ids and nil-matches-any triggering inport (#245), and per-process disable/enable with queued packets kept rather than dropped (#317); all commands require the `LIFECYCLE_CTRL` capability, with no dedicated ack frames — run-state changes ride the telemetry stream as `PAUSED`/`RESUMED` lifecycle events and breakpoint hits as `BREAKPOINT_HIT` events
- **fbp-protocol**: `0x44`/`0x45` live process listing codecs (work document #4 update #9): a bare request and the authoritative runtime view as `[0x45, epoch_id, {node: [component, kind, state]}]` — the declared component kind travels with every node so clients never infer stub-ness by joining names against their own registries, and the per-node execution state mirrors `0x43`; the listing is introspection and requires `GRAPH_READ`, not `LIFECYCLE_CTRL`
- **fbp-protocol**: `0x09 STUB_ERROR` flowtrace event type (work document #4 update #9): the canonical classification for errors raised by stub components — the payload is the exception string exactly as in `0x04 ERROR`, but the event type itself marks the error as unimplemented rather than a genuine component failure, with no string-parsing convention
- **fbp-protocol**: `0x46 CMD_HWM_SET` codec (work document #4 update #9): the runtime-global high-water mark as `[0x46, high_water_mark]` — non-negative integer (`0` synchronous, `n` up to `n` admitted in-flight packets) or nil (unbounded); the global default in the backpressure hierarchy, runtime configuration rather than graph state, observable through `0x0a EDGE_CAPACITY` samples. Edge-level high-water marks need no new wire surface: they travel as edge metadata inside `0x14` payloads, with changes projecting to tombstone + insert per #4 update #8
- **fbp-protocol**: `0x0a EDGE_CAPACITY` flowtrace event type (work document #4 update #9): per-edge backpressure sampling, one event per edge per flush with the `[edge_id, in_flight, desired_size]` payload — `desired_size` nil when the edge is unbounded, cadence riding the subscription's flush policy; a data-channel observation, never an error channel, feeding the noflo-ui high-water-mark route visual vocabulary
- **fbp-protocol**: Announce app_data (`msgpack([protocol_version, destination_hash_raw16, node_name])` per #4 updates #6/#7) and `0x02` auth response codecs with the version byte ahead of the capability mask, built on `@reticulum/core`'s zero-dependency MsgPack codec, with golden byte vectors pinning the wire layout
- **fbp-protocol**: `0x10` block CRDT graph codecs: epoch sync request with client logical clocks, up-to-date short-circuit, stale epoch with Reticulum Resource hash, and bidirectional `0x14` updates; the op taxonomy is now a *total* projection of the changeset reference model — insert ops for every structural entity kind (node `0x01`, edge `0x02`, IIP `0x03`, export `0x06`, group `0x07`, additive per #4 update #7), shared tombstone, UI metadata `0x05` — with the payload mapping documented per op (entity definition without id; `entity_id` carries it) and node renames projecting to tombstone + insert at the changeset→protocol boundary (#4 update #8)
- **fbp-protocol**: `0x20` block Two-Step Cache codecs: registry sync, the `0x21 CMD_COMP_UP_TO_DATE` match reply mirroring the graph block's `0x11` (the runtime always answers a sync request; silence never carries semantics), manifest (name → `[sig_hash, kind]` tuples carrying the declared component kind per #4 updates #9/#11, valid with signature and no source per #4 update #8), detail request/response carrying the declared component kind and the full #25 port field set as maps with absent optionals omitted, atomic source writes, and package install requests; plus the canonical signature and manifest serializations (sorted-key JSON) with SHA-256 `sig_hash` and `registry_hash` computation as the cross-repo alignment substrate with noflo-ui #43 (#4 update #10) — the registry-hash algorithm is now pinned, since it was previously unspecified on the wire
- **fbp-protocol**: `0x30`/`0x32` streaming telemetry codecs: pub/sub subscriptions with client-requested flush intervals, flowtrace chunks carrying delta-encoded `[time_delta_ms, event_type, payload]` tuples with uint32 delta validation, and a builder converting absolute-timestamped engine events into a chunk based at the earliest event
- **fbp-protocol**: `ProtocolError` carrying the offending opcode, thrown on truncated frames, unknown opcodes, wrong arities, and malformed payloads across all codecs
- **fbp-protocol**: AsyncAPI 2.6.0 interface document (`asyncapi.json`, CC0-1.0) describing one channel per command code with explicit direction, fixed-arity positional payload schemas, per-channel capability-mask requirements, and the RNS bootstrap transport (announce app_data schema and the `0x02` handshake), including the LXMF store-and-forward payload and the streamable trace file as non-link messages; machine-verified against the implementation by a test suite that decodes every wire example through the real codecs, re-encodes byte-for-byte, validates the documented decoded payloads against the wire bytes, and checks one-to-one parity between the channel table and the command constants (#4 update #7)
- **fbp-protocol**: Top-level `decodeFrame` dispatch: any link-level frame decodes through one entry point keyed by its leading opcode, returning a `cmd`-discriminated object; the `0xF0` trace snapshot is deliberately not dispatchable (file format, not a link frame)
- **graph**: The entity type vocabulary (`GraphPortRef`, `GraphNode`, `GraphEdge`, `GraphIIP`, `GraphExport`, `GraphGroup`, `EntityKind`) is now re-exported from the package root as documented types
- **runtime**: Initial package scaffold for `@noflo/runtime` (work document #28): the isomorphic FBP Protocol 2.0 runtime for NoFlo over Reticulum, superseding the `noflo-runtime-base`/`noflo-runtime-websocket` lineage with a Reticulum-only, protocol-2.0-only design
- **runtime**: `RuntimeServer.grantedFor()` and `RuntimeServer.canReceive()` accessors with an outbound capability map, letting transports filter broadcast fan-outs per context (work document #30)
- **runtime**: `ReticulumBinding` options `authorizeUnidentified` and `maxResources`, forwarded through `bindReticulum` (work document #30)
- **runtime**: `TelemetryProtocol` options `flushCeilingMs` (default 5 minutes) and `maxSubscriptionsPerContext` (default 32), with a `subscriptionlimit` event on exhaustion (work document #30)
- **runtime**: `GraphProtocol` option `maxKnownClocks` (default 1024) bounding the attacker-populated client clock map (work document #30)
- **runtime**: `assembleRuntime` options `permissions`, `capabilityPolicy`, and `limitationCode`, forwarded to the server core (work document #30)
- **runtime**: `RuntimeServer.resolveCapabilities()` — the one identity-based capability resolution path, consultable by transports; `authorize` is refactored onto it (work document #30)
- **runtime**: Baseline resource fetches now re-check the requester's identity-based capability decision (`GRAPH_READ`) on every fetch instead of serving to any linked peer holding the token — revocations bite the next fetch, and the token is reduced to addressing and integrity (work document #30)
### Changed
- **noflo**: `Subgraph` is constructed with its graph and network options: `new Subgraph(graph, options)` takes the same options a `Network` takes (`componentLoader`/`registry`/`flowtrace`/`asyncDelivery`/`highWaterMark`) plus `metadata`, builds its internal network from the constructor, and exposes the completion as `subgraph.prepared`. The parameterless constructor, the `setGraph` mutation method, and the vestigial `getComponent` factory export are gone — there is no graph-less shell state anymore
- **noflo**: `ComponentLoader.registerLoader` plugins are Promise-based: a `noflo.loader` plugin receives the loader and returns a Promise (or nothing) that settles when its registration work is done — the 1.x `(loader, callback)` completion-callback contract is gone. A synchronous throw or a rejected Promise fails the registration. Documented in the component loading and library migration guides
- **noflo**: The EventTarget support layer file is renamed: `LegacyEvents`/`LegacyEventBase`/`LegacyEventMixin` are now `EventBase.js`/`EventBase`/`EventTargetMixin` — the EventEmitter compat surface was removed in work document #8 and the module only carries the internal sync-dispatch machinery
### Fixed
- **noflo**: Subgraph internal networks are guarded against concurrent and redundant starts: `setUp` no longer stops-and-restarts an already-running internal network when the parent network (or an explicit `component.start()`) starts the subgraph after its implicit data-triggered start — a cycle that tore down internal component state and re-delivered initials. The guaranteed contract is that a subgraph delivers its internal IIPs during the network start that activates it (the parent network's start, or an explicit `start()`), before any data is processed; data sent to a never-started bare subgraph component before `start()` still races the implicit start and is not guaranteed to see the IIPs
- **runtime**: Security audit findings (work document #30): `0x27 CMD_COMP_INSTALL_REQ` now requires `COMPONENT_WRITE` and `0x10 CMD_CRDT_SYNC_REQ` requires `GRAPH_READ` — both were previously invokable by any peer, including fully denied ones, making the package-install hook reachable without authentication and the graph baseline fetchable without `GRAPH_READ`
- **runtime**: The server core now fails closed: contexts the transport never authorized are denied everything instead of falling back to the permissions store's default mask, closing the attacker-controlled pre-identification window and the DACAR bypass for peers that never identify (work document #30)
- **runtime**: Broadcasts no longer reach peers whose granted capabilities do not cover the frame (work document #30)
- **runtime**: The wire `entity_id` of a CRDT insert op is authoritative over a payload-supplied override (work document #30)
- **runtime**: Malformed hex identity/destination hashes fail loudly instead of silently resolving to zero-filled bytes (work document #30)
- **runtime**: `undecodable` event details carry at most a 256-byte diagnostic prefix of hostile bytes (work document #30)

## [2.0.0-alpha.2] - 2026-10-09

## [2.0.0-alpha.1] - 2026-10-08
### Removed
- **noflo**: The `debug` dependency: core runtime dependencies are now `@noflo/graph` alone
- **noflo**: **Registry-only component loading (work document #16)**: the Node.js loader (`fbp-manifest` discovery, `fbp.json` caching, TypeScript transpilation, CommonJS evaluation, `noflo.loader` plugin discovery) left core for the `@noflo/loader-node` package. Core consumes an application-supplied `ComponentRegistry` (`list`/`get`, optionally `setSource`/`getSource`, optionally EventTarget-based `change`/`invalidate`) plus manual `registerComponent` calls. Node.js applications await `createNodeModulesRegistry(baseDir)` and pass the ready registry; browsers pass a static ESM-URL registry with no build step
- **noflo**: `ComponentLoader(baseDir)`: the constructor is options/registry-only, readiness machinery is gone (registries are ready at handoff; the catalog is read synchronously at construction), and `baseDir` exits networks and `asCallback` — pass `componentLoader` or `registry` instead
- **noflo**: `loader.setSource`/`loader.getSource`/`loader.getLanguages`: source storage and language reporting are registry API only; runtimes call the registry they passed in, staying current through `change` events
- **noflo**: `loader.dynamicLoad` and path-string component definitions: definitions in core are platform-neutral values (factories, ESM module objects, live `GraphModel`s); discovered graph files register as pre-parsed models via the loader package
- **noflo**: The `Graph` loader catalog entry: the subgraph wrapper (`Subgraph`, renamed from `Graph`) is core machinery instantiated directly for graph definitions. The runtime `graph` inport on directly-instantiated subgraphs is deprecated; loader-loaded subgraphs never see it
- **noflo**: `fbp-manifest`, `@noflo/fbp`, and `get-function-params` dependencies: core runs on `@noflo/graph` alone
- **noflo**: `noflo.asComponent` and the `get-function-params` dependency: function-to-component wrapping moved to the standalone `@noflo/as-component` package (work document #16). NoFlo core does not import it back; applications `npm install @noflo/as-component` and call it directly
- **noflo**: `LegacyNetwork` and the `subscribeGraph` option: live graph subscription was the deprecated EventEmitter-based network variant; mutate networks via the network methods instead. Flowtrace recording now embeds FBP JSON graph definitions
- **noflo**: `noflo.loadFile` and `noflo.saveFile`: filesystem graph loading will move to a platform-specific package (`@noflo/nodejs`)
### Added
- **noflo**: The package is renamed to `@noflo/noflo` (work document #13): install with `npm install @noflo/noflo` or `jsr add @noflo/noflo`. Graph component identifiers are unaffected — component names using the unscoped `noflo/` prefix (for example `noflo/Split`) keep resolving, and the unscoped `noflo` npm package will receive a deprecation notice pointing at the scoped name
- **noflo**: Native-API debug logger (work document #17): `createDebug(namespace)` replaces the `debug` npm module with dependency-free code — namespace toggling via `localStorage` (browsers) or `DEBUG` (Node), wildcard and negation patterns with last-match-wins semantics, lazy per-call evaluation so patterns can change at runtime, stable per-namespace colors. Enabled namespaces log to `console.debug` (web) or `console.error` (Node, matching the `debug` module's stderr stream)
- **noflo**: The engine now runs the native `@noflo/graph` model as its core graph (work document #10): `noflo.createNetwork` and `Network`/`BaseNetwork` consume `GraphModel` instances directly, and the live-edit network methods (`addNode`/`removeNode`/`renameNode`/`addEdge`/`removeEdge`/`addInitial`/`removeInitial`) mirror their mutations back into the model. `GraphModel`, `importFbpJson`, and `exportFbpJson` are re-exported from NoFlo
- **noflo**: FBP JSON interchange is available through `noflo.importFbpJson`/`noflo.exportFbpJson`, including legacy NoFlo JSON documents (`processes`/`connections` shape) on import
- **noflo**: **Removed fbp-graph as the core data model**: networks are instantiated from native graph models only; the `Graph`, `graph`, `Journal`, and `journal` fbp-graph re-exports are gone
- **noflo**: `Edge` data-plane transport over Web Streams, the infrastructure for the 2.x dataflow migration: hierarchical `highWaterMark` resolution (edge metadata ∪ component default ∪ runtime global; `0` = synchronous, positive = buffered, `null`/absent = unbounded 1.x behavior), an `observe()` middleware hook for fbp-protocol/Flowtrace, bracket-substream integrity validation, and admission-based backpressure
- **noflo**: `getStream` on forwarding inports now returns the complete buffered stream including brackets (#545): the collection consumes the stream while mirroring the bracket-context side effects, so output forwarding keeps working
- **noflo**: `output.send()` (and `sendIP`/`pass` on process output) returns an admission Promise that resolves once the packet has been admitted by the receiving edge per its `highWaterMark`, enabling `await output.send()` backpressure in process functions. The Promise rejects on send errors — those also escalate through the socket error path (`process-error` with a listener, loud throw without) — and fire-and-forget callers are protected from unhandled rejections by internal handling. `OutPort` exposes the same promise per send as `lastWrite`
- **noflo**: Network-level `network.observe(callback)` middleware: sees every Information Packet on every edge before delivery, as `(ip, socket, next)` with socket context
- **fbp-spec-runner**: Initial implementation of the in-process fbp-spec runner: YAML (multi-suite) and JSON spec loading, `node:test`-based suite/case compilation with skip and timeout support, deterministic data-IP execution with pairwise input/expect sequences, and the full fbp-spec expectation operator vocabulary (`equals`, `above`, `below`, `type`, `haveKeys`, `includeKeys`, `contains`, `noterror`, `path`) mapped to `node:assert/strict`
- **fbp-spec-runner**: Vendored, version-pinned third-party bundles for JSONPath and YAML parsing (see `vendor/`), regenerable via `node utils/generate-vendors.js`
- **graph**: Initial plain-mode graph model: the five first-class entity kinds (Node, Edge, IIP, Export, Group) from work document #10, with referential integrity on plain mode, native `EventTarget` change events, node renaming with reference rewriting, and cascading node removal
- **graph**: Deterministic canonical serialization (`serialize`/`fromCanonical` plus `stableStringify`) as the foundation for content-addressed epoch snapshots
- **graph**: FBP JSON interchange adapter (`importFbpJson`/`exportFbpJson`) covering properties, nodes, edges, IIPs (`inits`), exported ports, and groups, including legacy NoFlo JSON documents (`processes`/`connections` shape) on import
- **graph**: Native array-port support: `index` is a validated, identity-participating field on port references — connections to different slots of the same port are distinct entities, with O(1) duplicate detection via a connection index
- **graph**: `component` is optional on nodes, allowing placeholder nodes that the engine registers without instantiating a process
### Changed
- **noflo**: The supported Node.js version is now >= 22 (maintainer decision on the 2.0.0 engines floor), raised from the interim `>= 20` shipping on the packaging branch
- **noflo**: Loading `.fbp` DSL files uses the `@noflo/fbp` parser package (work document #10). Files are parsed with legacy case-insensitive semantics — that is what the existing .fbp corpus means; the `@noflo/fbp` package default remains `caseSensitive: true` per the 2.x case-sensitivity policy for new code
- **noflo**: Network entity arguments speak the native `@noflo/graph` shapes: nodes are `{ entity_id, component, metadata }` instead of fbp-graph's `{ id, ... }`
- **noflo**: `Network.removeEdge` and `Network.removeInitial` throw when the graph holds no matching edge or IIP instead of silently ignoring the removal; when multiple IIPs target the same port, the first match is removed
- **noflo**: **Removed CoffeeScript component support** (`#539`-adjacent cleanup): `.coffee` component files are no longer transpiled or loaded; components must be JavaScript or TypeScript. Clear `Unsupported component source language` errors are emitted for `.coffee` sources
- **noflo**: **#607**: control-triggered firing reacts to any data IP arriving on a non-triggering inport, in any scope; the control IP stays buffered (a non-consuming standing gate) and each arrival is one firing edge. Reading the control value follows normal port scoping — declare the control port `scoped: false` when an unscoped standing control IP should gate scoped data (a scoped control port fed unscoped control IPs fires but the value is unreadable). Addressable control ports do not participate in control-triggered firing yet. This is a deliberate change from 1.x, where control ports never triggered firing; it is 2.x semantics to be documented in the migration guide
- **noflo**: `sendDone(null)` and `sendDone(undefined)` now only mark the process done instead of emitting a `data: null` packet
- **noflo**: InternalSocket `post` returns the edge admission Promise; rejections are escalated through the socket error path (side-channel handled, so fire-and-forget call sites stay rejection-free)
- **noflo**: Reformatted all source code to Biome standards
- **noflo**: Repository reorganized into a monorepo layout; the NoFlo npm package is now built from `packages/noflo`
- **noflo**: `ComponentLoader.registerComponent`, `registerGraph`, and `registerLoader` now return Promises; providing callbacks to them is deprecated and logs a warning
- **noflo**: `Component` now inherits from native `EventTarget` instead of Node.js EventEmitter. The legacy EventEmitter-style API (`on`, `once`, `off`, `removeListener`, `emit`, `listeners`) is provided by a compatibility mixin with deprecation warnings; internal engine dispatches go through a typed `dispatchLifecycleEvent` helper
- **noflo**: Networks now also inherit from native `EventTarget` with the same compatibility mixin. Network events (`start`, `end`, `icon`, `process-error`, `ip`, …) are dispatched as `CustomEvent`s with the payload in `event.detail`; subscribing via `addEventListener` works alongside the legacy `on` API
- **noflo**: Port collections and ports (`Ports`, `BasePort`, `InPort`) inherit from native `EventTarget` as well. Addressable port events carry `[payload, index]` as the event `detail` — `attach`/`detach` give `[socket, index]`, and forwarded socket events (`data`, `connect`, `disconnect`, brackets) give `[payload, index]`; the modern `ip` events keep the raw IP object with its `index` property.
- **noflo**: Event dispatch in NoFlo is synchronous like EventEmitter: listener exceptions propagate to the dispatcher instead of becoming uncaught exceptions as with native `dispatchEvent`. This keeps the engine's error-escalation chain working
- **noflo**: Node.js 18 is now the minimum supported version, matching the runtime requirements of the native `EventTarget`-based event system
